# User Flow — Личный диетолог Инга

Документ описывает текущий пользовательский путь по приложению.
Источник: `src/pages/Index.tsx` + экраны в `src/components/inga/`.

---

## 1. Вход в приложение

```text
[Открытие приложения]
        │
        ▼
  AuthScreen (auth)
   ─ Email/Password
   ─ Google
   ─ Apple
        │
        ├── Новый пользователь → survey-name
        └── Существующий       → hydrateFromDb()
                                  восстанавливает прогресс
                                  и переключает на нужный шаг
                                  (обычно `daily`)
```

Логика: `Index.tsx` слушает `auth.onAuthStateChange`. После успешной авторизации
вызывается `hydrateFromDb()`, который подтягивает профиль и решает, куда вести
пользователя.

---

## 2. Онбординг (первый запуск)

```text
survey-name      → ввод имени
     │
     ▼
goal             → выбор цели (похудение / поддержание / др.)
     │  ← «Назад» возвращает на survey-name
     ▼
why              → зачем худеешь / мотивация
     │  ← «Назад» → goal
     ▼
survey-data      → пол, возраст, рост, вес
     │  ← «Назад» → why
     ▼
tracking-method  → как будешь отслеживать
     │  ← «Назад» → survey-data
     ▼
how-it-works     → объяснение метода Инги
     │  ← «Назад» → tracking-method
     ▼
route-ready      → «Маршрут готов»
     │
     ▼
daily            → основной экран
```

### Дополнительные онбординг-экраны (доступны по флагам)

Эти экраны есть в кодовой базе и встроены в расширенный путь, но не входят в
базовую цепочку выше:

- `MeasurementsScreen` (`measurements`) → `pace-choice`
- `PaceChoiceScreen` (`pace-choice`) → `tracking-method`
- `GoalWeightScreen` (`goal-weight`) → `measurements`
- `CalculationsScreen` (`calculations`) → `goal-weight`
- `SurveyReasonsScreen` (`survey-reasons`) → `survey-emotions`
- `SurveyEmotionsScreen` (`survey-emotions`) → `calculations`
- `FoodTestScreen` / `FoodTestResultScreen` → `support-start`
- `SupportStartScreen` (`support-start`) → `daily`
- `WelcomeScreen` — приветствие / возобновление прохождения

## 3. Основной экран — Daily

`DailyScreen.tsx` — главный хаб после онбординга. Ширина ограничена 480px.

### Структура

```text
┌──────────────────────────────────────────┐
│  Шапка: дата · бейдж дня                 │
├──────────────────────────────────────────┤
│  Вкладки: [Утро] [Питание] [Вечер]       │ ← сохраняется в localStorage
├──────────────────────────────────────────┤
│                                          │
│  Контент активной вкладки                │
│                                          │
│  padding-bottom: 70px                    │
├──────────────────────────────────────────┤
│  Панель «Поговорим?»  (fixed bottom)     │ → ChatScreen
└──────────────────────────────────────────┘
```

Переходы со страницы:

- Кнопка «Меню»        → `menu`
- Панель «Поговорим?»  → `chat`

### Вкладка «Питание» — добавление приёма пищи

```text
[+ Приём пищи]
      │
      ▼
  Форма: описание + время + тип
      │
      ▼
  Сохранение → saveFoodLog (БД)            ─┐
      │                                     │
      ▼                                     │ fire-and-forget
  DeepSeek анализ белка (фон)              ─┘
      │
      ▼
  Карточка приёма с пилюлями:
   [✓ Белок] [✓ Углеводы] [✓ Клетчатка] [+ Сладкая точка]
      │
      ├── Включение «Белок» → inline-селектор порции:
      │     🤏 Меньше ладони · 🤚 Ладонь · 👐 Больше ладони
      │
      └── Любое изменение → PATCH в БД (фон)
```

Удаление карточки → `DELETE` в БД.

### Блок «Структура питания»

- Суммирует белок по выбранным порциям.
- Цель: `profile.weight * 1.5` (по умолчанию 80г).
- Подпись: «приблизительно, по методу ладони».

### Рекомендации Инги (на основе суммарного дня)

- Нет приёмов → «Добавь первый приём пищи…»
- Белок < 70% цели → «Белка пока маловато…»
- Клетчатка < 50% приёмов → «Маловато клетчатки…»
- Вода 5+, белок 80%+, клетчатка 60%+ → похвала.

`MenuScreen` — навигация и настройки.
Переход назад: `daily`.

## 5. Чат с Ингой

`ChatScreen` — диалог с AI-диетологом (DeepSeek через backend).
Шапка:
- «← Назад» → `daily`
- «Меню»   → `menu`

---

## 6. Сквозные правила

- **Авторизация обязательна** перед онбордингом и daily.
- **localStorage**: активная вкладка `dailyActiveTab` + дата
  `dailyActiveTabDate`. При смене дня — сброс на `morning`.
- **БД (Lovable Cloud / Supabase)**: профиль, `food_logs` (+ `meta` JSONB),
  чек-ины, чат-история. Все мутации — fire-and-forget.
- **Ограничение ширины**: основной контейнер и нижняя панель — max 480px,
  центрированы.
